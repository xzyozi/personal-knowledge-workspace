# Hybrid Skills 設計リファレンス

## 目的

共有Skillを「モデルの判断」と「スクリプトの決定的な処理」に分けて定義します。どのAIツールから呼んでも、同じ安全性と結果が得られるようにします。

[shared-agents.md](shared-agents.md) の共有Skillの上に載せる規約です。Skillの置き場、命名、frontmatterは変えません。

## 方針

| 担当            | 役割                                        | 例                                          |
| --------------- | ------------------------------------------- | ------------------------------------------- |
| スクリプト      | 検出、dry-run、検証、書き込み、秘密情報検知 | `reverse_bootstrap.py`、`init_knowledge.py` |
| モデル（Skill） | 目的の確認、候補の説明・下書き、結果の要約  | dry-run結果の説明、fact候補の抽出           |
| 人              | 採否の承認                                  | `--apply --confirm` を実行してよいかの判断  |

- 書き込みは必ずスクリプトが行い、モデルがファイルを直接書き換えません。
- スクリプトは既定がdry-runで、`--apply --confirm` の2つが揃った時だけ反映します（既存規約）。
- スクリプトは正本です。Skillはスクリプトの呼び出し手順と、承認の取り方だけを持ちます。

## Skillの定義形式

frontmatterは `name` と `description` の2項目のままです（`validate_structure.py` の既存検査を維持）。ハイブリッド性は、本文の固定見出しで表します。

```markdown
---
name: pkw-example
description: （200文字以内、`|` を含まない）
---

# pkw-example

## 目的
## 実行（スクリプト）
## 判断（モデル）
## 承認ゲート
## 出力形式
## 禁止事項
```

| 見出し             | 内容                                                                                               |
| ------------------ | -------------------------------------------------------------------------------------------------- |
| 実行（スクリプト） | 呼ぶスクリプト、dry-runのコマンド、applyのコマンド、終了コードの意味。スクリプトがない環境での扱い |
| 判断（モデル）     | モデルが行う範囲（候補の説明、下書き）と、行わない範囲                                             |
| 承認ゲート         | applyの前に、人へ何を見せて何を確認するか。承認がなければ止める                                    |

スクリプトを持たない純粋な手順型のSkill（例: `pkw-verify-knowledge-load`）は、「実行（スクリプト）」を「なし」と書きます。

## ツール差の扱い

- 手順は平文で書き、ツール固有のコマンドやAPIに依存しません。
- ツールごとに異なる確認コマンドは、Skill本文の表にまとめます（Claude Codeは `/memory`、Gemini CLIは `/memory show` など）。
- コマンドを実行できない環境では、その項目を「未確認」と報告させ、利用者に実行を依頼します。成功と報告しません。

## 昇格の2系統

### テンプレート昇格

ユーザー環境で修正したテンプレートを、リポジトリへ戻します。

- スクリプト: `scripts/reverse_bootstrap.py`（実装済み。[reverse-bootstrap.md](reverse-bootstrap.md)）。
- Skill: `pkw-promote-template`（新規）。dry-runを見せ、承認後に `--apply --confirm` を実行します。
- 判断（モデル）: UPDATEやWARNINGの意味の説明だけです。採否の判断は人が `git diff` で行います。

### fact昇格

`knowledge/04-sources/` の原本から、検証済みの事実を `knowledge/02-facts/` へ整理します。

- 条件と承認方法は、reverse-bootstrapの対象外です。次の「fact昇格の決定事項」で決めます。
- Skill: `pkw-promote-fact`（新規）。候補の抽出と下書きをモデルが行い、人が採否を決めます。
- スクリプト: 承認済みの下書きだけを `02-facts/` へ書き込み、秘密情報を検知します（新規。例: `scripts/promote_fact.py`）。

## fact昇格の決定事項（要確認）

次を決めてから実装します。

| 項目           | 案                                                                                                       |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| 昇格の条件     | 原本に出典がある。検証した日付と方法を書ける。秘密情報を含まない                                         |
| 下書きの置き場 | `knowledge/04-sources/04.00-inbox/` 配下の候補ファイル                                                   |
| 承認の方法     | 人が候補ファイルを確認し、スクリプトに `--apply --confirm` を渡す                                        |
| 書き込み先     | `knowledge/02-facts/`。分類は [分類ルール](../../knowledge/00-rules/00.04-classification-rule.md) に従う |
| 原本の扱い     | 原本は変更しない。fact側に出典の相対パスを書く                                                           |
| 取り消し       | Gitの差分で戻す。スクリプトは削除しない                                                                  |

## ネイティブSkillへの配布（別作業）

各ツールのSkill置き場へ配布する場合は、`<name>.md` を `<name>/SKILL.md` に変換します。

| ツール          | 置き場の候補                     | 状態                 |
| --------------- | -------------------------------- | -------------------- |
| Kiro            | `.kiro/skills/<name>/SKILL.md`   | 未実装               |
| Claude Code     | `.claude/skills/<name>/SKILL.md` | 未実装               |
| Antigravity CLI | `.agents/skills/<name>/SKILL.md` | 公式情報の確認が前提 |

正本は `knowledge/00-rules/skills/` のままで、配布先は変換した複製です。配布先の編集は、reverse-bootstrapの対象にしません。

## 検証

`validate_structure.py` に、次の検査を追加します。

- Skill本文に、固定見出し（目的、実行（スクリプト）、判断（モデル）、承認ゲート、禁止事項）がある。
- 「実行（スクリプト）」に書かれたスクリプトのパスが、リポジトリに存在する。
- スクリプトを使うSkillの「承認ゲート」に、`--apply --confirm` の記述がある。
- Skill本文に、絶対パスと秘密情報がない（既存検査を維持）。

## 実装順序

1. この設計の合意。
2. 既存の2つのSkillを、固定見出しの形式へ揃える。
3. `pkw-promote-template` を追加する（スクリプトは実装済み）。
4. `validate_structure.py` に見出しとスクリプトパスの検査を追加する。
5. fact昇格の決定事項を確定し、`pkw-promote-fact` と `promote_fact.py` を実装する。
6. ネイティブSkillへの配布を追加する。

## 範囲外

- ツール固有の機能（サブエージェント呼び出し、ツールの権限）。
- 外部ストレージとの同期。
- 実機確認の結果（#14に記録する）。
